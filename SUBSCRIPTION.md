# Подписка: что должна делать сторона ASCN

Продукт ставится на сервер клиента, а платит он нам. Здесь описано, что для
этого нужно поднять у себя. Сторона агента уже готова — она ходит по этому
контракту, и менять её не требуется.

## Как это держится

Проверку подписки в коде агента клиент может закомментировать: исходники у
него, Python не компилируется. Поэтому замков два, и они разной прочности.

**Мягкий — лицензия.** Установка раз в 12 часов спрашивает ASCN, оплачено ли,
и получает подписанный ответ. Просрочен — панель закрывается, боты гаснут.
Защищает от честной забывчивости, а не от злого умысла.

**Жёсткий — шлюз модели.** Агент отвечает клиентам через `GATEWAY_URL` по ключу
подписки. Ключи провайдеров у нас, поэтому вырезать проверку бессмысленно:
патчить надо не код, а наш сервер. Перестал платить — шлюз молчит, агент
физически не может ответить.

Отсюда правило продукта: **в маркетплейсной сборке ключ модели клиенту не
выдаётся**. Тариф «со своим ключом» ломает жёсткий замок и оставляет только
мягкий.

## 1. Сервер лицензий

Один эндпоинт.

```
POST {LICENSE_URL}/api/license/check
Content-Type: application/json

{
  "key": "ascn-xxxx-xxxx-xxxx",   // ключ подписки
  "install": "8f14e45fceea167a",  // идентификатор установки, живёт в её базе
  "url": "http://203.0.113.10:8000",
  "contacts": 128,                // для вашей статистики, на решение не влияет
  "leads": 34
}
```

Ответ — всегда `200` с подписанным токеном, даже если подписка кончилась: агенту
нужен заверенный ответ «не оплачено», а не голый код состояния.

```json
{ "token": "<base64url(payload)>.<base64url(signature)>" }
```

`payload` — JSON:

```json
{
  "key": "ascn-xxxx-xxxx-xxxx",
  "install": "8f14e45fceea167a",
  "plan": "pro",
  "until": 1789000000,
  "issued": 1788900000
}
```

- `until` — unix-время, до которого оплачено. **Выдавайте с запасом хотя бы в
  сутки** относительно срока проверки: пока он не истёк, установка работает без
  сети, и ваша недоступность не выключает агентов у платящих клиентов.
- `install` — привяжите к ключу при первой проверке. Пришёл другой `install` —
  либо не подписывайте, либо подпишите с прошедшим `until`: агент покажет
  «ключ уже используется на другом сервере».
- `404` — такого ключа нет. Любой другой код `>= 400` агент считает временной
  поломкой и продолжает работать по прежнему токену.

`signature` — RSA-подпись **байтов payload** алгоритмом SHA-256 (PKCS#1 v1.5),
приватным ключом ASCN. Публичный ключ ставится установке в `.env` как
`LICENSE_PUBLIC_KEY` (PEM в одну строку, переводы строк как `\n`); принимаются
оба формата PEM — `PUBLIC KEY` и `RSA PUBLIC KEY`.

Ключи делаются так:

```bash
openssl genrsa -out ascn-license.pem 2048
openssl rsa -in ascn-license.pem -pubout -out ascn-license.pub
```

Приватный не покидает ваш сервер. Публичный вписывается в сборку.

## 2. Шлюз модели

Совместим с OpenAI, чтобы установки не переделывать при смене провайдера.

```
POST {GATEWAY_URL}/v1/chat/completions
Authorization: Bearer <ключ подписки>
X-Install-Id: <идентификатор установки>

{"model": "ascn/base", "max_tokens": 2500, "messages": [...]}
```

- Подписка кончилась → `402`. Агент переведёт это владельцу как «подписка
  закончилась, продлите в кабинете», а не «ошибка 402».
- `GET /v1/models` — список доступных моделей в формате `{"data":[{"id":...}]}`.
  Недоступен — панель просто покажет текущую модель.
- `GET /v1/status` — живая проверка ключа для кнопки «Проверить ключ и модель».

Имя модели `ascn/base` — псевдоним: за ним стоит то, что вы выберете. Меняйте
провайдера и модель у себя, установки клиентов об этом не узнают.

## 3. Что положить в сборку для маркетплейса

В `.env` установки:

```
LICENSE_REQUIRED=1
LICENSE_URL=https://ascn.ai
GATEWAY_URL=https://gateway.ascn.ai
LICENSE_PUBLIC_KEY=-----BEGIN PUBLIC KEY-----\nMIIB...\n-----END PUBLIC KEY-----\n
```

`LICENSE_KEY` можно не вписывать: владелец введёт ключ в панели, на странице
«Подписка». Так установка проходит без ввода секретов в файл на сервере.

Установкам, которые клиент поднял сам и платит провайдеру напрямую, ничего
менять не нужно: `LICENSE_REQUIRED=0` по умолчанию, и подписка не проверяется.

## 4. Что происходит у клиента, когда подписка кончилась

| Что | Как ведёт себя |
|---|---|
| Боты во всех каналах | погашены; вебхуки отвечают `402` |
| Агент | не обрабатывает сообщения, даже если они дошли |
| Панель | закрыта, любой адрес ведёт на страницу «Подписка» |
| Рассылки и автоцепочки | не отправляются |
| Данные | целы: страница подписки отдаёт архив с перепиской, лидами, базой знаний и вложениями |
| Продление | нажал «Проверить подписку» — боты поднимаются сами, настраивать заново нечего |

Данные не удаляются и не прячутся никогда. Удержание чужой переписки — это не
защита от неплатежа, а причина для возврата платежа и жалобы.

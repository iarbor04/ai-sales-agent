# ИИ-продажник для Telegram и WhatsApp

Клиент пишет бизнесу в мессенджер — агент отвечает по базе знаний компании,
уточняет потребность, заводит лида и при необходимости передаёт разговор
менеджеру. Менеджер отвечает из веб-панели, клиент получает ответ там же,
где написал. Через Telegram-бота владелец рассылает сообщения подписчикам.

Разворачивает и обслуживает это ИИ-агент — инструкция для него в
[AGENT.md](AGENT.md). Этот файл для человека.

## Что умеет

**Диалог.** Отвечает коротко и задаёт не больше одного вопроса за сообщение.
Только по загруженной информации бизнеса — цены, сроки и условия не выдумывает.
Не знает ответа — зовёт человека, а не фантазирует.

**Семь каналов.** Telegram (сколько угодно ботов), чат на сайте, WhatsApp
Business, MAX, ВКонтакте, Авито, почта. Отвечает один и тот же агент с одной
базой знаний, вся переписка сходится в «Диалогах».

**Лиды воронкой.** Карточка заводится сама, когда собрано хотя бы пара полей:
имя, контакт, продукт, срок, комментарий. Этапы воронки настраиваете вы,
карточки перетаскиваются мышью. Второй карточки на того же человека не появится.

**Передача менеджеру.** Срабатывает, когда клиент просит человека, готов
покупать, жалуется, просит особые условия или задаёт вопрос без ответа в базе.
Назначается ответственный, приходит уведомление с кнопками «Взять в работу» и
«Передать», в карточке остаётся резюме. Кнопка «Вернуть ИИ» возвращает агента
в диалог — он продолжает с учётом всей истории.

**База знаний.** Прайс таблицей (xlsx, csv), документы (DOCX, TXT, Markdown),
страницы сайта по домену и поле «вписать руками». Столбцы с закупкой, наценкой
и поставщиком агенту не показываются. Есть проверка: вводите вопрос как клиент
и видите ровно то, что получит модель.

**Рассылки.** Текст на языке клиента, картинка, до трёх кнопок, отбор
получателей по этапу воронки. Обязательный предпросмотр и подтверждение.
Сразу или по расписанию. Повторная отправка не создаёт дублей, клиенты на
финальном этапе воронки не получают ничего.

**Автоцепочки.** Догоняющие сообщения для тех, кто написал и замолчал. Ответил
сам — остаток снимается, дальше разговор ведёт агент. Ушёл к менеджеру — тоже
снимается.

**Модель на выбор.** OpenRouter (сотни моделей одним ключом) или YandexGPT
(оплата в рублях, данные в Яндекс.Облаке). Переключается вкладкой в настройках.
Отказ провайдера объясняется человеческими словами: отозванный ключ, пустой
счёт и недоступная модель — это разные сообщения, а не «ошибка».

**Онлайн-запись и конкуренты.** Запись клиента на свободное время с
напоминанием; слежка за страницами конкурентов с уведомлением об изменениях.

**Самопроверка.** Раз в час служба проверяет себя: поднялись ли боты, принят ли
ключ модели, не пуста ли база знаний, не зависли ли задания. О поломке пишет
менеджеру один раз, о восстановлении — тоже.

## Установка

```bash
git clone https://github.com/iarbor04/ai-sales-agent.git ai-sales && cd ai-sales
bash deploy/install.sh
nano .env          # пароль панели, PUBLIC_URL, при желании MODE=webhook
bash deploy/deploy.sh
```

Установка ставит python-venv, sqlite и nginx, создаёт окружение, генерирует
`SECRET_KEY` и поднимает службу. Токен бота и ключ модели в `.env` вписывать не
нужно — они вводятся в панели.

Свежая установка пустая: ни лидов, ни переписок, ни настроенных каналов. Дальше
владелец открывает панель, проходит «Мастер запуска» и подключает бота.

Обновление и состояние:

```bash
bash deploy/deploy.sh    # свежий код, зависимости, перезапуск
bash deploy/status.sh    # версия, служба, здоровье
bash deploy/reset.sh     # вернуть установку в пустое состояние
```

Проверка перед выкаткой — самопроверка проекта, сети и ботов не требует:

```bash
.venv/bin/python selftest.py
```

Публичный HTTPS-адрес и WhatsApp:

```bash
bash deploy/nginx.sh sales.example.com
```

## Что нужно подготовить

| Что | Где взять |
|---|---|
| Токен Telegram-бота | @BotFather |
| Ключ модели | openrouter.ai или YandexGPT в Яндекс.Облаке — вписывается в панели |
| WhatsApp Business | кабинет Meta: постоянный токен и Phone Number ID |
| Домен | нужен для WhatsApp; для Telegram достаточно IP |

## Как это устроено

**Один процесс.** Боты, планировщик и панель поднимаются вместе.
Останавливается и обновляется одной командой.

**SQLite вместо СУБД.** Переписка, лиды и очередь рассылок в одном файле.
Схема донакатывается сама при старте — миграции руками не нужны.

**Поиск по базе знаний без внешних сервисов.** BM25 на стандартной библиотеке,
с учётом русских окончаний: «на зиму» находит «Сезон: Зима». Пока база влезает
в запрос, она уходит в модель целиком — на маленьком каталоге поиск не нужен и
только мешает. Ни ключей, ни отдельного сервера.

**Восемь зависимостей и ни одной системной.** Разворачивание не требует
компиляции, docker и внешних сервисов: python, sqlite и nginx.

**Модель ошибается — клиент не страдает.** Недоступна модель или пришёл мусор
вместо ответа — диалог уходит менеджеру. Пустое сообщение клиенту не
отправляется никогда.

## Ограничения

- WhatsApp работает только через вебхуки и требует HTTPS: Cloud API не умеет
  long polling. Ещё Meta запрещает писать первым вне окна в 24 часа — поэтому
  рассылки идут только в Telegram.
- Картинка к сообщению одна, альбомы не поддерживаются.
- PDF в базу знаний не грузится: чтение PDF требует сторонней библиотеки, а
  коробка держится на стандартной. Сохраните документ как DOCX.
- Загруженные файлы не обновляются сами: поменяли прайс — залейте заново.
- Синонимы поиск не угадывает: если клиенты спрашивают «шапку», в прайсе лучше
  писать «шапка-ушанка», а не только «ушанка».
- Рассылка идёт с паузой между сообщениями, чтобы не поймать лимиты Telegram:
  несколько тысяч подписчиков — это минуты, а не секунды.
- Голосовые и видео сохраняются, но не расшифровываются.

# AGENT.md — инструкция для ИИ-агента, который это разворачивает

Читай этот файл первым. Здесь всё, что нужно, чтобы поднять проект на VPS,
проверить его и починить, не заглядывая в исходники.

## Что это

ИИ-продажник для Telegram и WhatsApp. Клиент пишет в мессенджер, агент
отвечает по базе знаний бизнеса, собирает лида и при необходимости передаёт
разговор живому менеджеру. Менеджер работает в веб-панели этого же проекта.
Через Telegram-бота владелец рассылает сообщения подписчикам.

Один процесс Python: боты, планировщик и веб-панель. База — SQLite в файле.
Ни docker, ни брокеров очередей, ни отдельного фронтенда.

## Правила работы с этим проектом

Соблюдай их, иначе будешь ловить таймауты и думать, что всё сломалось.

1. **Длинные команды запускай в фоне и читай лог.** `install.sh` идёт
   несколько минут — твой вызов шелла столько не живёт.
   ```
   setsid nohup bash deploy/install.sh > install.log 2>&1 < /dev/null &
   ```
   потом отдельными вызовами: `tail -5 install.log`
2. **Никогда не запускай `journalctl -f` и `tail -f`** — это бесконечный
   поток, вызов повиснет. Используй `bash deploy/logs.sh 50`.
3. **Все команды идемпотентны.** Повторный запуск не ломает, а доводит до
   нужного состояния. Если сомневаешься — просто запусти ещё раз.
4. **Схему базы накатывать не нужно.** Приложение при старте само добавляет
   недостающие колонки. Отдельной команды миграции нет.
5. **Состояние проверяй одной командой** — `bash deploy/status.sh`. Она
   отдаёт строку, которую можно показать владельцу как есть.

## Развернуть с нуля

```bash
# 1. Забрать код
cd /opt
git clone <АДРЕС_РЕПОЗИТОРИЯ> ai-sales
cd ai-sales

# 2. Установка (в фоне, ~3-5 минут)
setsid nohup bash deploy/install.sh > install.log 2>&1 < /dev/null &

# 3. Ждать, проверяя лог отдельными вызовами
tail -5 install.log

# 4. Вписать ключи
nano .env        # или sed -i, если правишь программно

# 5. Применить
bash deploy/deploy.sh
```

Что обязательно вписать в `.env`:

| Переменная | Где взять | Без неё |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather в Telegram | канал Telegram выключен |
| `OPENROUTER_API_KEY` | openrouter.ai | агент молчит и зовёт менеджера |
| `ADMIN_PASSWORD` | придумать | вход в панель под `admin/admin` |
| `PUBLIC_URL` | адрес сервера или домен | ссылки в уведомлениях будут битые |

WhatsApp и HTTPS — отдельно, когда есть домен:

```bash
bash deploy/nginx.sh sales.example.com
```

Скрипт поднимет nginx, выпустит сертификат, переключит `MODE=webhook` и
перезапустит службу. После этого в кабинете Meta укажи вебхук
`https://ДОМЕН/hook/whatsapp` и тот же verify token, что в `.env`.

## Где что лежит

```
run.py                 запуск: боты + планировщик + панель в одном процессе
app/
  config.py            всё из .env, ничего не зашито в код
  db.py                схема, миграции, работа с контактами и лидами
  sales.py             ПОВЕДЕНИЕ АГЕНТА — правила диалога собраны здесь
  llm.py               OpenRouter: ответ, извлечение полей, решение о передаче
  knowledge.py         обход сайта клиента, страницы в базу знаний
  retrieval.py         поиск по базе знаний (BM25 на стандартной библиотеке)
  broadcast.py         рассылки: черновик → предпросмотр → подтверждение
  scheduler.py         фоновый цикл: отложенные рассылки, повторы
  notify.py            уведомления менеджеру в Telegram
  channels/
    base.py            единая отправка, не важно TG или WA
    telegram.py        бот на aiogram
    whatsapp.py        Meta Cloud API
  web/main.py          все маршруты панели
  web/templates/       страницы панели
deploy/                скрипты из таблицы выше
```

Если правишь поведение агента — тебе нужен `app/sales.py` и промпт в
`app/llm.py`. Остальное трогать почти никогда не нужно.

## Проверка после установки

Прогони по порядку, это чек-лист приёмки из ТЗ.

```bash
# 1. Служба жива и отвечает
bash deploy/status.sh

# 2. Панель открывается
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/login   # 200

# 3. Страницы закрыты без входа
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/        # 303
```

Дальше руками, через панель:

1. Открой панель, войди под логином из `.env`.
2. **База знаний** → впиши домен клиента → «Найти страницы» → сними лишние
   галочки → «Сохранить и загрузить». Проверь поиск в блоке «Проверить».
3. Напиши боту в Telegram — диалог появится в **Диалогах**.
4. Задай 2-4 вопроса — в **Лидах** появится карточка. Напиши ещё раз —
   вторая карточка появиться не должна.
5. Напиши «хочу поговорить с менеджером» — ИИ замолкает, статус становится
   «Передан менеджеру», в чат менеджера приходит уведомление.
6. Ответь из панели — ответ придёт клиенту в Telegram.
7. Нажми «Вернуть ИИ» — агент продолжит с учётом всей истории.
8. **Рассылки** → создай → посмотри предпросмотр → подтверди → проверь,
   что доставлено. Нажми «Повторить неудачные» — дублей быть не должно.

## Что делать, когда сломалось

| Симптом | Что смотреть | Как чинить |
|---|---|---|
| `status.sh` говорит «не отвечает» | `bash deploy/logs.sh 50` | чаще всего опечатка в `.env`; исправить и `deploy.sh` |
| Бот не отвечает в Telegram | лог, строка «Telegram» | пустой или неверный `TELEGRAM_BOT_TOKEN` |
| Бот молчит, а менеджеру всё падает | `/health` → поле `ai` | нет `OPENROUTER_API_KEY` — это штатное поведение при недоступной модели |
| Агент отвечает «не знаю» на всё | панель → База знаний | база пустая: страницы не загружены или все галочки сняты |
| Агент выдумывает цены | панель → Настройки | так быть не должно; проверь, что база знаний загружена, и напиши об этом владельцу |
| WhatsApp не принимает | `.env` → `MODE` | должно быть `webhook` и HTTPS; Cloud API не умеет polling |
| Рассылка ушла дважды | `broadcast_log` в базе | этого не может быть по схеме; если случилось — сохрани лог и сообщи |
| Порт занят после падения | `ss -tlnp \| grep 8000` | `systemctl restart ai-sales` |

## Чего делать нельзя

- **Не удаляй `data.db`** — там вся переписка и лиды. Сначала `backup.sh`.
- **Не правь схему руками** через sqlite3. Добавь колонку в `LATE_COLUMNS`
  в `app/db.py`, приложение накатит её само при следующем старте.
- **Не коммить `.env`** — там токены. Он уже в `.gitignore`.
- **Не подключай Telegram как канал ASCN.** Бот подключается токеном от
  BotFather сюда, в проект. Канал ASCN увёл бы переписку в воркспейс агента,
  и менеджер не смог бы отвечать из панели — это прямо запрещено в ТЗ.
- **Не запускай второй экземпляр** на том же токене: Telegram отдаёт апдейты
  только одному потребителю, боты начнут отбирать сообщения друг у друга.

## Если владелец просит поменять поведение

| Просьба | Где править |
|---|---|
| «пусть отвечает мягче/жёстче» | панель → Настройки → Тон общения |
| «пусть не спрашивает срок» | `app/llm.py`, промпт `_system_prompt()` |
| «карточку заводить раньше» | `.env` → `LEAD_AFTER_FIELDS=1` |
| «пусть чаще зовёт человека» | `app/sales.py` → `HUMAN_WORDS` |
| «добавить ещё один мессенджер» | новый модуль в `app/channels/` + строка в `base.send()` |

После любой правки кода: `bash deploy/deploy.sh` и `bash deploy/status.sh`.

# AGENT.md — инструкция для ИИ-агента, который это разворачивает

Читай этот файл первым. Здесь всё, чтобы поднять проект на VPS, проверить его
и починить, не заглядывая в исходники.

## Что это

ИИ-продажник для Telegram и WhatsApp. Клиент пишет в мессенджер, агент отвечает
по базе знаний бизнеса, собирает лида и при необходимости передаёт разговор
живому менеджеру. Менеджер работает в веб-панели этого же проекта.

Один процесс Python: боты, планировщик и панель. База — SQLite в файле.
Ни docker, ни брокеров очередей, ни отдельного фронтенда.

**Токены ботов в .env не нужны.** Владелец добавляет ботов сам в панели,
раздел «Боты». В .env только доступ к панели и адрес.

## Правила работы с этим проектом

Соблюдай, иначе будешь ловить таймауты и думать, что всё сломалось.

1. **Длинные команды — в фон, потом читай лог.** `install.sh` идёт 3–5 минут,
   вызов шелла столько не живёт.
   ```
   setsid nohup bash deploy/install.sh > install.log 2>&1 < /dev/null &
   ```
   дальше отдельными вызовами: `tail -5 install.log`
2. **Никогда не запускай `journalctl -f` и `tail -f`** — это бесконечный поток,
   вызов повиснет. Только `bash deploy/logs.sh 50`.
3. **Все команды идемпотентны.** Повтор не ломает, а доводит до нужного
   состояния. Сомневаешься — запусти ещё раз.
4. **Схему базы накатывать не нужно.** Приложение при старте само добавляет
   недостающие колонки и при необходимости пересобирает таблицы.
   Отдельной команды миграции нет и не должно быть.
5. **Состояние — одной командой:** `bash deploy/status.sh`. Она отдаёт строку,
   которую можно показать владельцу как есть.

## Что взять у клиента до начала

Доступы даёт клиент, и брать их надо сразу — иначе упрёшься на середине.
Спроси одним сообщением:

| Что нужно | Зачем | Без этого |
|---|---|---|
| IP сервера и имя пользователя | подключиться | никак |
| SSH-ключ (приватный) | вход без пароля | никак |
| root или sudo без пароля | поставить пакеты и службу | `install.sh` зависнет молча |
| Домен, указывающий на сервер | HTTPS и WhatsApp | Telegram будет работать и без домена |

Ключ положи в «Секреты и ключи» воркспейса, а не в переписку и не в файл
проекта. Токен бота и ключ OpenRouter спрашивать **не нужно** — их владелец
вводит сам в панели после запуска.

## Как попасть на сервер

Если ты работаешь из песочницы ASCN, а разворачивать надо на VPS — сначала
подключение. Песочница пересоздаётся, и установленные в неё пакеты при этом
пропадают, поэтому проверяй наличие клиента каждый раз, а не один раз в начале.

```bash
# ssh-клиент: в песочнице его может не быть после пересоздания
command -v ssh || apk add --no-cache openssh-client

# ключ из раздела «Секреты и ключи» кладём в файл с правами 600
mkdir -p ~/.ssh && chmod 700 ~/.ssh
printf '%s\n' "$VPS_KEY" > ~/.ssh/id_deploy && chmod 600 ~/.ssh/id_deploy

# проверка связи
ssh -i ~/.ssh/id_deploy -o StrictHostKeyChecking=no USER@IP 'echo связь есть; whoami'
```

Дальше каждую команду из этой инструкции выполняй через `ssh`, помня про
таймаут: долгие команды запускай на сервере в фоне и опрашивай лог отдельными
вызовами.

**Нужен root или sudo без пароля.** `install.sh` ставит пакеты и службу systemd.
Если `sudo` попросит пароль, скрипт зависнет и ты этого не увидишь — проверь заранее:

```bash
ssh -i ~/.ssh/id_deploy USER@IP 'sudo -n true && echo "sudo без пароля есть" || echo "НУЖЕН ПАРОЛЬ — скажи владельцу"'
```

## Развернуть с нуля

```bash
# 1. Забрать код
cd /opt
git clone <АДРЕС_РЕПОЗИТОРИЯ> ai-sales
cd ai-sales

# 2. Установка в фоне (~3-5 минут)
setsid nohup bash deploy/install.sh > install.log 2>&1 < /dev/null &

# 3. Ждать, проверяя лог отдельными вызовами
tail -5 install.log

# 4. Задать доступ к панели
#    install.sh уже создал .env и сгенерировал SECRET_KEY
sed -i 's#^ADMIN_PASSWORD=.*#ADMIN_PASSWORD=ПРИДУМАЙ_ПАРОЛЬ#' .env
sed -i 's#^PUBLIC_URL=.*#PUBLIC_URL=http://IP_СЕРВЕРА:8000#' .env

# 5. Применить
bash deploy/deploy.sh
```

Всё. Дальше владелец открывает `PUBLIC_URL`, входит под `admin` и паролем
из `.env`, и панель сама ведёт его по настройке — раздел «Настройка»
показывает, что осталось сделать.

Что нужно в `.env` — и это весь список:

| Переменная | Зачем | Без неё |
|---|---|---|
| `ADMIN_PASSWORD` | вход в панель | будет `admin` — небезопасно |
| `SECRET_KEY` | подпись сессий | install.sh сгенерировал сам |
| `PUBLIC_URL` | ссылки в уведомлениях и вебхуки | ссылки будут битые |

Токен Telegram и ключ OpenRouter задаются **в панели**, лезть в файл не нужно.
Прайс загружается туда же файлом — xlsx или csv, раздел «База знаний».

## Публичный HTTPS и WhatsApp

```bash
bash deploy/nginx.sh sales.example.com
```

Скрипт поднимет nginx, выпустит сертификат Let's Encrypt, переключит
`MODE=webhook`, поправит `PUBLIC_URL` и перезапустит службу.

Домен должен уже указывать A-записью на этот сервер, иначе certbot откажет.

После этого в кабинете Meta: вебхук `https://ДОМЕН/hook/whatsapp`, verify token —
тот же, что в `.env` в `WHATSAPP_VERIFY_TOKEN` (только латиница, он уходит в URL).
Сам доступ к WhatsApp — `WHATSAPP_TOKEN` и `WHATSAPP_PHONE_ID` в `.env`.

Для Telegram домен не обязателен: в режиме polling бот работает и на голом IP.

```
    base.py            единая отправка, не важно TG или WA

    whatsapp.py        Meta Cloud API
  web/main.py          все маршруты панели
  web/templates/       страницы панели
  web/static/          стили и логотип

```

Правишь поведение агента — нужны `app/sales.py` и промпт в `app/llm.py`.
Остальное трогать почти никогда не нужно.

## Проверка после установки

```bash
# 1. Служба жива и отвечает
bash deploy/status.sh

# 2. Панель открывается
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/login   # 200

# 3. Страницы закрыты без входа
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/        # 303

# 4. Что видит приложение о себе
curl -s http://127.0.0.1:8000/health
# {"ok":true,"channels":[...],"ai":true/false,"model":"...","contacts":N,"leads":N}
```

Дальше владелец проходит «Настройку» в панели — шаги там отмечаются сами,
когда условие выполнено. Твоя часть на этом закончена.

## Что делать, когда сломалось

| Симптом | Что смотреть | Как чинить |
|---|---|---|
| `install.sh` молчит и не заканчивается | `tail -20 install.log` | скорее всего `sudo` ждёт пароль; нужен root или sudo без пароля |
| `ssh: command not found` | песочница пересоздалась | `apk add --no-cache openssh-client` заново |
| `Permission denied (publickey)` | права на ключ | `chmod 600 ~/.ssh/id_deploy`, проверить, что ключ добавлен на сервер |
| `status.sh` говорит «не отвечает» | `bash deploy/logs.sh 50` | чаще всего опечатка в `.env`; исправить и `deploy.sh` |
| Панель не открывается снаружи | firewall, `PUBLIC_URL` | открыть порт 8000 или поставить nginx |
| Бот не отвечает в Telegram | панель → «Боты», колонка состояния | у бота будет написана ошибка; обычно неверный токен |
| Бот молчит, всё падает менеджеру | `/health` → поле `ai` | нет ключа OpenRouter — это штатное поведение, ключ вставляют в панели |
| Агент отвечает «не знаю» на всё | панель → «База знаний» | база пустая: страницы не загружены или все галочки сняты |
| WhatsApp не принимает | `.env` → `MODE` | должно быть `webhook` и HTTPS; Cloud API не умеет polling |
| Meta не принимает вебхук | `WHATSAPP_VERIFY_TOKEN` | только латиница: токен уходит в URL |
| Порт занят после падения | `ss -tlnp \| grep 8000` | `systemctl restart ai-sales` |
| Два бота отбирают сообщения | `ps aux \| grep run.py` | запущено два экземпляра; оставить один |

## Чего делать нельзя

- **Не удаляй `data.db`** — там вся переписка, лиды и подключённые боты.
  Сначала `backup.sh`.
- **Не правь схему руками** через sqlite3. Добавь колонку в `LATE_COLUMNS`
  в `app/db.py` — приложение накатит её само при следующем старте.
- **Не коммить `.env`** — он в `.gitignore`, там пароль от панели.
- **Не подключай Telegram как канал ASCN.** Бот подключается токеном от
  BotFather в панели проекта. Канал ASCN увёл бы переписку в воркспейс агента,
  и менеджер не смог бы отвечать из панели — это прямо запрещено в ТЗ.
- **Не запускай второй экземпляр** на тех же токенах: Telegram отдаёт апдейты
  одному потребителю, боты начнут отбирать сообщения друг у друга.

## Как вносить изменения

Порядок жёсткий, не пропускай шаги:

```bash
# 1. правишь файл
# 2. проверяешь, что ничего не сломал — 5 секунд, сеть не нужна
.venv/bin/python selftest.py

# 3. только если проверка прошла
bash deploy/deploy.sh
bash deploy/status.sh
```

`selftest.py` гоняет 27 проверок: синтаксис, все шаблоны, маршруты, схему
базы и главные инварианты поведения — контакт не двоится, лид не двоится,
рассылка не уходит дважды, «стоп» выключает ИИ, вопрос вне базы знаний уходит
человеку. Работает на временной базе, боевую не трогает. Сломано — печатает
что именно и возвращает код 1.

**Если проверка красная — не деплой.** Почини и запусти снова.

## Каналы: что проверено, а что нет

| Канал | Источник, по которому сделано | Гонялось на живом |
|---|---|---|
| Telegram | aiogram, официальная библиотека | да |
| Чат для сайта | наш собственный | да |
| MAX | официальный SDK max-botapi-python | нет, аккаунта не было |
| ВКонтакте | документация API, методы проверены запросом | нет, сообщества не было |
| Почта | стандартная библиотека, IMAP и SMTP | нет, ящика не было |
| Авито | официальный OpenAPI-спек каталога | нет, кабинета не было |

Отдельно про MAX: страница документации указывает базу `platform-api2.max.ru`
и токен в заголовке Authorization. Это неверно — такой хост не резолвится.
Рабочий адрес `botapi.max.ru`, токен идёт query-параметром `access_token`,
как в официальном SDK. Не «чините» это обратно по документации.

Если канал не работает, первым делом смотри разбор входящего события
(`_extract` в модуле канала) — там у всех неподтверждённых платформ
намеренно мягкий разбор, и туда же добавляй недостающее поле.

## Куда смотреть при типовых правках

Половина просьб решается в панели, без кода. Сначала проверь эту таблицу.

| Просьба владельца | Где править | Код нужен? |
|---|---|---|
| «пусть отвечает мягче/жёстче» | Настройки → Тон общения | нет |
| «пусть задаёт другие вопросы» | Сценарий | нет |
| «пусть не идёт по сценарию» | Боты → снять галочку | нет |
| «поменять приветствие» | Боты → приветствие бота | нет |
| «добавить второго продажника» | Боты → добавить | нет |
| «сменить модель» | Настройки → Модель | нет |
| «подключить прайс» | База знаний → загрузить xlsx или csv | нет |
| «залить регламент или договор» | База знаний → загрузить PDF или DOCX | нет |
| «карточку заводить раньше/позже» | `.env` → `LEAD_AFTER_FIELDS` | нет |
| «пусть чаще зовёт человека» | `app/sales.py` → `HUMAN_WORDS` | да |
| «не выключать ИИ на слово X» | `app/sales.py` → `STOP_WORDS` | да |
| «поменять правила ответа» | `app/llm.py` → `_system_prompt()` | да |
| «другие поля у лида» | `app/db.py` → `LEAD_FIELDS` + `LATE_COLUMNS` | да |
| «новый раздел в панели» | `app/web/main.py` + шаблон рядом | да |
| «добавить мессенджер» | модуль в `app/channels/` + ветка в `base.send()` | да |
| «поменять вид панели» | `app/web/static/style.css` | да |

Правила, которые держат проект простым, — соблюдай их, и следующему агенту
будет так же легко:

- **Новая колонка в базе** добавляется только в `LATE_COLUMNS`. Приложение
  накатит её само при старте. Руками через sqlite3 — никогда.
- **Новая настройка** — в `DEFAULT_SETTINGS` в `app/db.py`, читается через
  `db.setting()`. В код значения не зашиваем.
- **Новая страница** — маршрут в `app/web/main.py` через `page(request, ...)`,
  шаблон наследует `base.html`. Меню правится в `base.html`.
- **Отправка клиенту** — всегда через `channels.base.send()`, никогда напрямую
  через telegram или whatsapp: иначе сообщение не попадёт в переписку.
- **Новая проверка в selftest** к каждой заметной правке. Пять строк, но
  следующий, кто полезет в этот код, скажет спасибо.

# Один продукт: рассылка внутри ИИ-продажника

19.08.2026

## Зачем

Два продукта — ИИ-продажник (Python, 7 каналов, ИИ, база знаний) и рассылка
(Next.js, канбан, мультиязычные рассылки, автоцепочки) — делят Telegram, лиды,
диалоги и настройки. Держать их порознь нельзя технически: **один бот не может
обслуживаться двумя процессами** — при polling Telegram отдаёт 409, а webhook
указывает ровно на один адрес. Значит либо клиент пишет продажнику, либо
рассыльщику, а лиды живут в двух несвязанных базах.

Решение: база — продажник, из рассылки переносятся три функции. Рассылка как
отдельный проект закрывается.

Модель продажи — коробка: один клиент, одна установка. Мультиарендности нет.
Данные рассылки не переносятся: боевых установок у неё нет.

## Этапы лида

Зашитые `new / qualifying / handed` заменяются настраиваемыми этапами:
`pipeline_stages(id, title, color, position, is_won, is_system)`. При первом
запуске засеиваются текущими тремя, поэтому существующие лиды не ломаются.

Два этапа защищены от удаления:

- `is_system` — куда падает лид при передаче менеджеру (`hand_off`);
- `is_won` — финальный, исключается из рассылок.

`leads.status` хранит id этапа и не требует миграции. Константа
`LEAD_STATUSES` уходит; названия этапов подставляются в промпт модели.

## Рассылки

Переносится: варианты текста по языкам, до трёх кнопок, фильтр получателей по
этапу. Требуется новое поле `contacts.language` — сейчас язык не хранится, а без
него мультиязычность невозможна. Заполняется из `language_code` Telegram и языка
браузера для виджета; для остальных каналов пусто и уходит русский вариант.

Фильтр по каналу не делаем: рассылать можно только в Telegram. WhatsApp
запрещает писать первым вне окна 24 часов, чат на сайте адресата не имеет.

## Автоцепочки

`autochains`, `autochain_steps`, `autochain_jobs`. Шаг уходит, только если после
постановки в очередь от клиента не было сообщений — то есть цепочка работает для
молчунов, а разговор ведёт ИИ. Передача менеджеру отменяет остаток. Обработка
заданий — в существующем планировщике, отдельный таймер не нужен. Задания,
зависшие в `processing` после перезапуска, переклеймиваются.

## Интерфейс

«Лиды» — канбан с перетаскиванием и настройкой этапов. «Рассылки» — языковые
вкладки, кнопки, фильтр по этапу, предпросмотр. Новый раздел «Автоцепочки».
Оформление — карточками, как на странице «Боты».

## Коннекторы моделей (следующий заход)

Провайдеры выносятся в `app/providers/`: `openrouter`, `yandex` (YandexGPT
Foundation Models), `gigachat`. Каждый умеет отправить запрос, проверить ключ и
отдать список моделей. В настройках — выбор провайдера и его поля: ключ для
OpenRouter, ключ и folder id для YandexGPT, client id с secret и обновляемый
OAuth-токен для GigaChat. Перевод ошибок провайдера на человеческий язык уже
есть и обобщается на всех.

## Чего не делаем

Мультиарендности, миграции данных рассылки, переписывания на React, биллинга,
рассылок в WhatsApp.

## Проверяемость

Каждая перенесённая функция получает проверку в самотесте (на момент решения —
131), сеть не нужна. Отдельно проверяется миграция на копии боевой базы: старые
статусы становятся этапами, лиды не теряются.
